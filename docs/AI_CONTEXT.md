詳細驗收與限制：`docs/V04_UI_SPEC.md`。`src/game/data/uiConfig.ts` 管理分頁數，`src/game/data/ambientThoughts.ts` 管理內心話，`src/game/data/cardLore.ts` 管理卡牌背景與來源，`src/features/settings` 管理兩頁共用的音量控制與關卡設定。

# 跨對話開發入口（AI_CONTEXT）

**現在的任務**：開發《餘燼紀事》敘事卡牌 RPG Prototype v0.1。請先閱讀 `GAME_DESIGN.md`、`PROTOTYPE_SCOPE.md` 與 `GAME_DATA_SCHEMA.md`。

**設計重點**：

1. 手機與 Web 使用同一套直式置中 UI；React + Vite + TypeScript。
2. 玩家所見行動卡皆以主角第一人稱內心想法撰寫，NPC 保留角色自己的台詞。
3. 每個行動卡顯示成功率與可預見代價；附加技能後立即重算。重大臨界值附上影響與恢復方式。
4. NPC 具有持續記憶、對特定手法適應；玩家每次戰敗保證取得下次有用情報。
5. 戰敗不可奪走玩家已取得物品。撤退每次都要明確確認，存在可恢復的負面代價。
6. 搜刮與選項消耗世界時間；NPC 後續按五個時段出沒。
7. 永久屬性 18 種，專精成長緩慢，通常每個支線只提高一項永久屬性。
8. 同一張卡牌升級五階：普通 5/8/10/12，稀有半數進位，混沌每階一張。
9. 原型不應提前假裝實作完整 100 物品、六職業、跨職業親授、黑市、溫度系統；在 `PROTOTYPE_SCOPE.md` 打勾才算完成。

**程式原則**：

- 遊戲引擎與 React UI 分離。
- UI 不自行發明另一套規則；從 `game/engine/rules.ts` 呼叫純函式預覽。
- 不用 AI API 決定實際遊戲狀態，保持可測試、確定性和成本可控。
- 請保留既有存檔向後相容設計。
- 重要修改同時更新文件與自動測試。

**接續開發的推薦順序**：先修好任何測試與手機介面問題，然後豐富一個關卡；再增加多 NPC 資料模型與日夜行程；最後擴充卡牌、倉庫與黑市。
