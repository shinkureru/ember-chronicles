# 最新開發交接（v0.4）

前一版本為 v0.3。本版本已在既有 React/Vite/TypeScript 專案新增卡牌 3×4 圖鑑與卡牌故事、固定裝備按鈕空間、地圖六格選單、場景主導布局、120 段場景心聲、可用技能脈衝提示、關卡設定／手動存檔、倉庫每頁 15 筆與較清晰音效。地圖頁因已集中入口，所以隱藏重複的底部導覽，放大關卡地圖。

詳細驗收與限制：`docs/V04_UI_SPEC.md`。`src/game/data/uiConfig.ts` 管理分頁數，`src/game/data/ambientThoughts.ts` 管理內心話，`src/game/data/cardLore.ts` 管理卡牌背景與來源，`src/features/settings` 管理兩頁共用的音量控制與關卡設定。

**請注意**：npm registry 在製作環境無法連線，TypeScript/TSX 語法檢查已通過，尚無法保證在使用者瀏覽器中的完整畫面與音效運作；本機應執行 `npm install && npm run build && npm test` 並以手機測試後再視為通過。

# 跨對話開發入口（AI_CONTEXT）

**現在的任務**：開發《餘燼紀事》敘事卡牌 RPG Prototype v0.1。請先閱讀 `GAME_DESIGN.md`、`PROTOTYPE_SCOPE.md` 與 `GAME_DATA_SCHEMA.md`。

**設計重點**：

1. 手機與 Web 使用同一套直式置中 UI；React + Vite + TypeScript。
2. 玩家所見行動卡皆以主角第一人稱內心想法撰寫，NPC 保留角色自己的台詞。
3. 每個行動卡顯示成功率與可預見代價；附加技能後立即重算。重大臨界值附上影響與恢復方式。
4. NPC 具有持續記憶、對特定手法適應；玩家每次戰敗保證取得下次有用情報。
5. 戰敗不可奪走玩家已取得物品。撤退每次都要明確確認，存在可恢復的負面代價。
6. 搜刮與選項消耗世界時間；NPC 後續按五個時段出沒。
7. 永久屬性 18 種，專精成長緩慢，通常每個支線只提高一項永久屬性。
8. 同一張卡牌升級五階：普通 5/8/10/12，稀有半數進位，混沌每階一張。
9. 原型不應提前假裝實作完整 100 物品、六職業、跨職業親授、黑市、溫度系統；在 `PROTOTYPE_SCOPE.md` 打勾才算完成。

**程式原則**：

- 遊戲引擎與 React UI 分離。
- UI 不自行發明另一套規則；從 `game/engine/rules.ts` 呼叫純函式預覽。
- 不用 AI API 決定實際遊戲狀態，保持可測試、確定性和成本可控。
- 請保留既有存檔向後相容設計。
- 重要修改同時更新文件與自動測試。

**接續開發的推薦順序**：先修好任何測試與手機介面問題，然後豐富一個關卡；再增加多 NPC 資料模型與日夜行程；最後擴充卡牌、倉庫與黑市。

## v0.3 最新決定（2026-11-07）

- 使用者決定 Web 優先，以 GitHub Pages 發布公開測試，未來再考慮 App Store；直式遊戲畫面共用於桌面與手機。
- 全遊戲黑色為核心、灰黑暗紅恐怖氣氛，不要可愛或明亮感。Google Fonts 採 Noto Sans TC／Inter，標題 Noto Serif TC。
- 設定頁調整總音量、背景恐怖音樂、場景環境音、所有操作及事件音效。每次點擊、受傷、體力下降、跑步、衝突等皆需回饋；背景／氛圍隨關卡轉換，下水道預留滴水及回音音效。
- 正式進入關卡時鎖定主選單，不能進地圖、牌組、倉庫、人物、設定頁（即使直接修改 URL 也應阻擋）。
- 任何取得卡牌、戰利品、情報、重大事件、生命變化都要有明顯提示；重要事件需確認，嚴重事件加強彈跳震動。
- 一個直式視窗完成操作，關卡不允許整體垂直捲動：選項分頁、技能抽屜、劇情全文彈窗；牌組、倉庫、黑市、人物與設定也改成分頁／標籤，盡量不用垂直捲動（開發者面板例外）。
- 本次版本將 GitHub Pages workflow、HashRouter、Vite base 設定寫入專案，未上傳 GitHub；不要聲稱已部署。
- 音效目前使用原創程序合成，未含第三方錄音；日後需逐一驗證授權，尤其真人痛楚、喘息、腳步、打擊與正式配樂。
- 一定要區分企劃已確定、程式已寫好、已通過型別與規則測試、已在手機瀏覽器驗證等不同完成狀態。
- 使用者訊息末尾的「8.」無內容，先按 1–7 點實作。
