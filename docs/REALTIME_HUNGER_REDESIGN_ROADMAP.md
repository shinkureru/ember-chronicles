## 第6～8批高風險規則（先規劃，未實作）
1. `GameContext.tsx` 有 `WORLD_TICK_REAL_MS=10000` / `WORLD_TICK_GAME_MINUTES=5`，`gameReducer` 處理 `WORLD_CLOCK_TICK`；`townActions.ts` 目前 `applyTownService` 回傳 `service.minutes`、城鎮日次數依 `s.world.day`，`innRest.ts` 用 `world.day` 計每日休息。第6批必須同時處理，不能只替換 UI 時計。
2. `ActionDecision.tsx` 和 `calculateActionPreview` 有 `時間 +X 分`、`choice.minutes`；`rules.ts`、`resolve.ts` 還會因選擇/退場加時間。新制度應移除實際加速與所有舊文案，並用嚴格等價成本回歸防漏。
3. `player.hunger` 舊規則為**數字愈高愈餓**：`consumables.ts` `p.hunger-20` 和 `townActions.ts` 熱飯 `p.hunger-38`，`ThoughtWhisper` 在 `hunger>70` 提醒。新成本必須 `+飢餓`，最多100；飢餓高門檻可增加操作警告與效率衰退，完整平衡與提示放第7批。
4. 「睡覺不消耗時間」是**遊戲數值不快轉**，台北現實時間當然仍隨現實流逝，不應凍結/調快真實時鐘。進場/切場景不應收飢餓；玩家明確執行有體力負荷的活動才收，避免反覆點頁無意增加成本。
5. 每批優先檢查前批 PR 已 Merge、main SHA、open PR、`docs/PROJECT_HANDOFF.md`、相關 TSX/引擎/SCSS/既有 Vitest，保留每批隔離與使用者合併停點。
