# 2026-11-13｜餘燼紀事：第二輪高密度 UI 重設計（8 批，逐批 Merge）

## 原則與工作協定

- 工作開始前**每次**透過 GitHub 讀 `docs/PROJECT_HANDOFF.md`，核對最新 `main` SHA、未合併 PR、上次 CI／部署、目標 TSX／SCSS、引擎及測試。以最新 GitHub 為準，不把歷史交接狀態誤認為當下狀態。
- 每批**一個分支／一個 PR／專項 Vitest／QA 文件／更新永久交接**，CI 需 `npm run build` + `npm test` 全綠；如有失敗限在同一個 PR 修正。使用者自行 Merge，明確通知後才開始下一批；未授權不合併、不跨批做事。
- 以手機置中直式 UI 為設計基準，兼容桌面瀏覽器；每頁先訂尺寸預算及優先級。正常裝置尺寸盡量一頁式，超小視窗或長文只讓指定內容面板捲動，不裁切按鈕及必要資訊。保留手動拖曳、觸控、鍵盤與無障礙標籤。
- 深色壓抑風格、卡片邊距、字級層次、可點擊區、短文字、長名字、無內容及不夠貨幣等失敗狀態均納入 QA；絕不為壓縮而犧牲遊戲數據或存檔安全。
- 截圖是視覺設計參照，不代表要複製其中其他遊戲的名稱、圖像、美術素材或原始碼。

## 每批實務驗收矩陣

1. 桌面 1280×800、720×1176；手機 CSS viewport 390×844、360×740、320×568；另驗橫置小高度、200% 文字縮放。
2. 同頁切換不同資料量（有／無裝備、完整／不足貨幣、短／長名字、0／滿資源）時，固定頁籤與底部行為不跳動。
3. 可見介面操作、hover、focus、鍵盤 Tab/Enter/Esc、滑鼠拖曳、滾輪、觸控滑動均需檢查。
4. CI 需檢查 TS + Vite + Vitest；實機 UI 驗收須由使用者在 Merge 後確認，不能把原始碼斷言當成已完成瀏覽器截圖測試。
