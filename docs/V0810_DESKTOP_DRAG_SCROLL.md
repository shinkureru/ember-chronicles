## 問題與修正

原有共用 `useVerticalDragScroll` 依賴 React 容器上 `onPointerMove`，且跨越位移門檻後才要求 `setPointerCapture`。高速拖曳移出容器、跨越卡片或進入瀏覽器原生拖曳時，可能無法持續更新 `scrollTop`。黑市還存在另一套只在局部監聽的拖曳邏輯。

- 共用 Hook 在 document **capture** 階段接收滑鼠 `pointermove`，監聽全域 `pointerup`、`pointercancel` 與 `blur`；卸載時釋放監聽與定時器。
- 開始操作限定左鍵滑鼠、可實際垂直捲動的區域；表單/可編輯控制不攔截。超過 **7px** 才視為拖曳；進入拖曳後避免文字選取及原生影像拖走，結束時恢復選取設定。
- 以「起始 `scrollTop` 減去當下累積位移」計算，避免重複 document/React move 事件造成加速或跳動。
- 拖曳後短暫抑制 React click capture，避免意外點選裝備部位／商品；單純點擊仍能選擇。**不使用強制 pointer capture**，避免捲動手勢和子元素事件衝突。
- 黑市 `BlackMarketPage` 統一使用相同 Hook（原有選取彈窗與交易事件照舊）；工坊、旅店、城鎮、其他設施、卡牌圖鑑自動沿用修正。診所保留已有 document-level 邏輯與 `resetToTop`，避免同批不必要的重構。
- 手機原生 `touch-action:pan-y`、滾輪、鍵盤 `tabIndex`、隱藏捲軸及原版排版不動。

## 人工 QA（CI 不能取代）

1. 桌面 Chrome / Edge：在 **修理工坊** 裝備部位與檢修卡按住滑鼠上下拖曳，快速將游標移出詳情區再移回，內容仍順暢移動，放開滑鼠即停止。
2. 連續點擊四個部位：點擊不應被錯當拖曳，拖曳不應意外切換部位或觸發修理／精工按鈕。
3. 在 **黑市** 商品卡上按住並拖曳，拖曳不能誤開商品詳情；單擊卡片、切換購買/出售及交易仍可用。
4. 在城鎮八設施、旅店預覽、卡牌圖鑑、其他設施彈窗重複相同操作，跨子元素及快速拖曳都不掉幀或突然停住。
5. 滑鼠滾輪與鍵盤依舊可瀏覽；手機與觸控板原生垂直捲動不受影響；捲動到底後 footer 可操作。
6. 短視窗與狹窄畫面檢查；不將後續版型問題當作本批已修正。
