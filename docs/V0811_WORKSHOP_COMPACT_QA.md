# v0.8.11｜修理工坊四部位精簡與詳情穩定

## 範圍／來源

2026-11-13 GitHub `main` `59a952d43e7ae49bfcf301cf7b8fb0945b5b3548`，PR #36 的 v0.8.10 桌面拖曳已合併、Pages push 部署成功；建立本分支時沒有 open PR。分支 `fix/v0.8.11-workshop-compact-layout`；**僅做工坊排版**。

參考使用者第二張標註圖。原有四張部位卡兩欄各約 96px 高，佔用大量垂直空間；同一捲動容器同時包含部位選擇、裝備詳情，有裝備/未裝備內容高度落差，容易造成切換後資訊位置移動。v0.8.4 為固定 92dvh 視窗，並未徹底解決單頁密度與部位切換造成的視覺位移。

## 本批 UI 規則

1. **固定區塊：** 原標題／工坊插畫、四部位選擇區、底部「返回避難所」均保持可見且位於正常 Flex 版面；只有中間 inspection/empty 詳情可 scroll。並保留關閉按鈕、Esc、遮罩點擊與暫停世界時間。
2. **桌面排列：** 在 viewport >= 640px 時選擇區四欄一列，卡片至少 88px（其餘靠文字自動撐高）。寬度 < 640px 時兩欄兩列，每張至少 72px；短高視窗有專門壓縮，內容絕不因變高隱藏。
3. **版面密度：** 工坊主視窗上限由 850px 收斂至 770px、主場景至 79px；標題與 footer 縮短。檢修資訊改為緊湊但完整的裝備識別、耐久、雙防禦值、兩個操作按鈕、修理規則與狀態消息。
4. **文字與資訊完整性：** 防具名稱／磨損狀態預留不同列高度，字體與內距隨裝置縮放並使用 `minmax(0,1fr)` + `overflow-wrap:anywhere`；不強制單行截斷。長修理規則保留全文，詳細區可捲動，禁止標籤與邊框互擠。
5. **切換穩定：** 四卡設置 `aria-pressed` 與 `aria-controls`。選擇新部位只更新 `selected`，並將詳情容器 scrollTop 歸零。選擇區和 footer 不隨詳細內容變動，未裝備狀態共用同一詳細捲動視口，空裝備不再塞 220–340px 高的空白。
6. **保護系統：** 使用 v0.8.10 共用 Hook；不修改 `armorHits`、`armorDurability`、`getEquippedDefense`、`getTownServiceLock`、`getTownServiceFee`、`TOWN_SERVICE`、perfect repair、材料、時間、戰鬥、路由和存檔格式。

## 手動驗收（使用者 Merge 後做）

1. Chrome/Edge 1280×800、720×1176：彈窗四欄一列，盡量一個視窗看全所有修理內容；若有長內容，可直接拖曳/滾輪查看，header/footer 不動。
2. 390×844、360×740、320×568：四部位維持兩欄、字體不破框，長防具名可換行；中間詳情可拖曳/觸控，footer 不擋操作。
3. 循環點頭部/身體/手臂/腿部，混用未裝備、正常與中度/嚴重損壞，詳情永遠從頂端開始；選擇卡與 footer 不因長文字、空欄跳動。
4. 修理和精工升級各試一次（足額/不足舊幣、無材料、無磨損、達 3/3 等），操作仍正確，費用、效果數值與停用原因如實顯示。
5. 桌面拖曳、滾輪、鍵盤上下、手機原生觸控、Esc/叉叉/遮罩/返回避難所功能皆正常。
6. 不把 CI 成功當成視覺已人工驗收。若高度不足時只能捲動，接受這個正常的 RWD 降級，禁止裁切關鍵內容。
