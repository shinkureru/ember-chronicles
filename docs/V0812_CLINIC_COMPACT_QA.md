## 版型設計與失敗情境

1. 與既有 v0.8.6 一致，**每個治療結果仍為垂直單欄排列**，每個指標保持完整長條；不轉回早期微型雙欄卡。
2. 原本「標籤／改善量」與「前後數值」分佔兩行，改為同一排左右分佈，底下接 9px 厚長條。指標卡內距由 10–11px 降為 8–10px；文字尺寸依內容微調。長文字可以自然換行而不與右側數值相撞。
3. 360px 以下視窗，採單欄三行（標籤、前後數值、進度條）回退，不以文字溢出換取高度。小視窗高度也縮小內距，但保持所有變化量可讀。
4. 僅以 `src/styles/_v0812-clinic-compact-outcomes.scss` 實作，於 `main.scss` 最後載入，以精準選擇器覆蓋 v0.8.6 的 `display:block!important` 及相關間距；**不修改 ClinicDialog JSX 或醫療計算引擎**。
5. 不影響分頁「每日委託」與「專屬藥房」、可滾動/滑鼠拖曳、治療按鈕、阻擋原因、價格、時間、診所好感、遊戲狀態、儲存資料或世界時間。原進度動畫與 `prefers-reduced-motion` 規則沿用。
6. 為了維持辨識度，保留標籤字型層次、結果數字對比、分隔線與色彩標準。內容多於兩項結果時繼續向下堆疊，主內容容器本身負責捲動，不裁切卡片。

## 使用者 Merge 後的手動驗收

1. Chrome / Edge 桌面 1280×800 及 720×1176：以「外傷清創與包紮」檢查生命與外傷兩張小卡。須保留原顏色、完整 `6/10 → 10/10`／`6 → 4` 和 +/− 差值、9px 雙色進度條，整體高度比舊版明顯下降。
2. 手機 390×844、360×740、320×568：標籤/右側數字不撞在一起；320px 採較高但安全的三行布局。當卡片多於兩張時可順暢觸控上下捲動。
3. 選擇不同醫療服務：只有實際有效的指標才顯示，無改善顯示原本的空狀態；沒有損壞的時候，鎖定原因及按鈕仍可正常顯示。
4. 嘗試足額/不足舊幣、治療後再看結果，對照實際生命/外傷變化；時間推進仍可能另外影響飢餓與疲勞，預覽僅顯示直接效果。
5. 切換每日委託及專屬藥房，確認 UI 沒有改動、購物/委託可操作；Esc／叉叉／離開診所、滾輪／拖曳／鍵盤瀏覽都正常。
6. CI 通過不等於真正瀏覽器視覺測試通過。若場景長文字或短螢幕需捲動，應能完整看到內容及底部操作，不宣稱強制所有高度完全一頁式。
