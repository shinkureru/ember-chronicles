## 精細 UI 說明
1. 三個頁面共用新的 **`character-v0819`** 視覺框架（標題/小英文眉標、右側摘要、格線、深灰/暗銅金/淡紅階層及固定內距）。僅對 `character-v0819` 作用；不影響其他人物頁或各個設施 UI。
2. **城鎮成長**：四張較小、資訊高度一致的卡片（今日訓練、完成委託、身體狀況、裝備改良）。手機一般兩欄×兩列，至少600px的內容寬度才改四欄。每張卡上排標籤及目前值、下一行保留原本的訓練、委託、受傷/感染/中毒/疾病、工坊說明。底部短提示卡保留原來永久成長／成本的內容。
3. **NPC 記憶**：上方四個摘要（嘗試次數、情報、倉庫/後巷事件數），接著兩個 NPC 的緊湊「固定數據」卡（敵意、來訪、交涉適應、攻擊適應、我擊敗敵人／我被擊敗、專屬下次判定加成）。必須維持 NPC ID `warehouse_guard` 和 `alley_watchman` 的獨立資料，不把和平行動誤當戰鬥勝利。
4. NPC 長篇戰鬥記憶改用**原生 `<details><summary>`**，預設收合、點開才顯示全部紀錄，最新的記憶排在最前，包含每次次數、方法、NPC 心聲與效果。不足紀錄時仍有原本的「尚未被我以戰鬥手段擊敗」提示。記錄內容很多時限制僅內部 log 的高度，允許局部滾動，不能裁掉故事與數字。
5. **情報清單**另外提供「已掌握的關鍵線索 N 條」收合，展開後讀 `s.clues.slice().reverse()` 的**完整所有字串**，最長文字可以換行且可在清單內捲動，0 條時仍顯示原本的空狀態。保留 NPC 倉庫/後巷的全部原有資料、動態值與獨立記憶。
6. **人物故事**：原先的兩段第一人稱引言、角色專業介紹 `profession.overview`、被動技能 `profession.passive` 全保留，依「故事引言 → 角色經歷 → 職業天賦 → 結尾」分為較精簡的敘事塊。不同職業長度不同時自然換行，不能透過 CSS 截斷故事。
7. 主要手機直式 390×844 / 360×740 / 320×568 及桌面視窗適配。三頁摘要應在正常高度一頁內展示；當 NPC 詳情展開、文字過長、200% 字級或視窗很短時**僅人物內容面板/明確的 log/線索清單**允許捲動。五個主分頁不得被頁面內容推走。
8. 遵守鍵盤 Tab/Enter/Space 原生 details 展開、focus-visible、觸控與滾輪。全程保留 `npc-defeat-record`、`npc-defeat-record__log`、`clue-list` 既有類別，避免舊故事／記憶樣式契約失效。

## 使用者 Merge 後手動 QA
1. 桌面 Chrome／Edge 1280×800、720×1176；手機 390×844、360×740、320×568。城鎮四摘要應整齊不錯位，數值不互相疊在卡片外，底部提醒可見。
2. 兩個 NPC 均無戰鬥紀錄的初期存檔：兩卡應小巧，原本的空記憶提示完整可讀；上方各項數據要與實際 state 一致。
3. 模擬兩個 NPC 各打贏多次，尤其各自10筆或更多記錄：兩名 NPC 記憶不能混在一起；每個「戰鬥記憶 X 則」可獨立展開並在紀錄內捲動；所有方法、心聲、加成可讀且沒有遮蔽 footer。
4. 擁有很多條或非常長的線索：一開始只顯示資訊總數，展開後仍可閱讀每條原文字；0 條時出現「還沒有取得關鍵線索」。
5. 切換記者、滲透者、外送騎士的故事頁面：角色名、原背景、原被動、兩段原引言都仍完整顯示，長字不裁切。
6. 使用鍵盤 Tab 及 Enter/Space 展開、收合，手機觸控／桌面滾輪上下閱讀，200% 字體放大、600×360 橫向短視窗時不會被迫看不到內容或操作。
7. 回切全身裝備、屬性，確認前兩批的裝備／加點不退步。冒險模式的人物頁路由鎖仍照舊。
