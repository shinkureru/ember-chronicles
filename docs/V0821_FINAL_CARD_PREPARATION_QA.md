## 攻擊圖鑑：具體設計與檢查
1. 三個頂部入口仍為「功能／附加技能」「攻擊型主動牌」「事前準備」。全部/已持有、稀有度（全部/普通/稀有/混沌）、職業（所有/共通/記者/滲透者/騎士）**套用在兩種卡牌**。各分類篩選狀態獨立保留，切換與調整捲回格子頂部。原收藏計數/技能20/攻擊5正確。
2. 攻擊型網格同樣四欄、高密度，原 emoji、稀有度、五階邊框色、獨立 LV/數量/未取得鎖；新增來自 `getAttackDamage(state,id)` 的實際傷害，`ATTACK_CARDS[id].baseChance` 基礎成功率，`staminaCost` 體力成本，`ITEMS[requiredItemId].name` 必備武器。
3. 物品狀態取自 `attackStatus`：已取得的卡顯示「背包有／倉庫有／缺武器」；未取得的卡仍鎖定。注意**倉庫有 ≠ 一定符合15kg負重**；詳情提示至準備頁完成確認。不可假稱倉庫物品等同已能出牌。
4. 點開攻擊卡的詳情維持原有說明/攻擊數據/故事/取得方式、各等級 I–V 與獨立 LV.I 複本、真實升級素材、`UPGRADE_CARD`；攻擊詳情縮小內距但不可裁切任何長字和按鈕。原功能卡圖鑑與其 `chanceBonus`、`resourceCost` 不應受攻擊卡 CSS 影響。
5. 四欄可區內滾動、滑鼠拖曳/滾輪/觸控，鍵盤 Tab/Enter/Esc 可用。空結果（如稀有度混沌+職業交集）要能顯示原空狀態，且頂部/底部不被推走。

## 事前準備：具體設計與檢查
1. 新增「返回牌組圖鑑」入口且原「返回地圖」仍在。標題顯示目前 `mission.name`；四項摘要：已選張數/5、可用張數、實際背包重量/15 kg、逐張計算倉庫備妥後的預估重量，所有值動態從 state 讀取。
2. 上方五個實際攻擊槽始終完整顯示。點已選槽移除，空槽顯示「＋」。狀態分「已備妥」「倉庫可備妥」「負重不足」「缺少物品」並保留原白/紅視覺差異。最多五張仍由 reducer 強制，滿五張點新卡不應超量。
3. 下方「擁有的攻擊型主動牌」改成顯示原 emoji、卡名、簡介、實際傷害、基礎成功率、體力成本、必備武器及背包／倉庫／缺少狀態的可選卡。點擊只使用 `PREPARE_ATTACK_CARD`，原倉庫有物品時由 reducer 決定是否可領出（15 kg 負重），不是直接在 UI 修改 bag/warehouse。
4. **未選任何卡／選中無武器卡仍可以進關**：按「帶著這些準備進關」先顯示原警告及返回調整／「我知道了，仍要進關」兩按鈕，明確確認才 `START_ATTEMPT` 並 `navigate('/chapter')`。武器不在背包的攻擊進戰鬥後仍不可使用，這由既有戰鬥引擎判定。
5. 無牌時顯示原空狀態，仍可無攻擊卡進關；武器在背包、倉庫以及兩處皆無的三種組合；負重剛好15 kg和超限；五張選滿/取消/再加入；高數量卡和長中文名不遮住下方警告/返回/設定。
6. 正常手機直式只下方卡片格可滾（約390px：兩欄卡；<=380px：一欄；>=650px：三欄）。橫置極矮高度<480px 或文字200%時整個準備內容允許安全垂直捲動，**操作不得裁切**。內區滾輪與觸控/鍵盤 focus 不應造成選牌誤觸。
7. 320×568／360×740／390×844／720×1176／1280×800 目視主要入口、五槽、狀態摘要、格子與 footer；600×360／200%縮放核對底部「開始任務」與警告視窗可達。
