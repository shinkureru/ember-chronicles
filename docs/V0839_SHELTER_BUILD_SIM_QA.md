## 自動 CI
- `npm run build` TypeScript/Vite 必須全綠。
- `npm test` 既有遊戲回歸 + 新 `tests/v0839-shelter-build-simulator.test.ts` 皆應全綠。
- 禁止自動測試為了綠燈而移除舊有測試條件，除了歷史版本/最後樣式匯入斷言需要同步外，保留原有資產 checksum 確認。
- CI 不能替代真實瀏覽器點擊、UI 操作與所有手機尺寸視覺檢查。

## 使用者手動驗收
1. 在已選廢棄倉庫的存檔進首頁，先看空景。向下滑到「家具建設測試」。
2. 按「購入下一件」：畫面出現1件，進度1/8；按「重洗路線」應只換待購順序，不刪除已買的1件。
3. 按「自動建造」：約每850ms加入1件，新圖層漸入；按「停止播放」後不繼續加入；8/8 自動停止並切背景為 `background_full.jpg`。
4. 按「隨機3件」「隨機5件」「隨機0～8件」反覆測試，注意會重新指定家具擁有集合及排列，畫面透視/陰影仍符合原使用者位置與Z遮擋。不要因先買 radio 沒 workbench 就自動給 workbench；懸浮視覺問題保留待美術/設計決策。
5. 按「一鍵滿配」→顯示原高品質滿圖；按「清空家具」→回到空倉庫，不刪人物、裝備、NPC、城鎮進度或舊幣。
6. 直接點八件家具個別按鈕可以任何順序取得/撤銷，沒有前置限制；每次畫面和已有集合對應。
7. 中途購入5件後刷新：應先播放一次 v0.8.36 全螢幕封面，回到5/8，所購家具與本次排列都還在。選職業前後也不能清除購置紀錄。
8. 若首選**廢棄公寓**，主畫面為公寓占位；按「預覽倉庫家具建設」進入倉庫建築演示，買/刪家具後按「返回我的避難所」，公寓占位不變。重新整理也不能把公寓選擇改成倉庫。
9. 再進遊戲設定「刪除本機存檔並重啟」才會把所有原型進度一併刪除；快捷「清空家具」只有家具集合被清空。
10. Chrome 桌機及手機 320/360/390/768/1280 寬、200% zoom、520px以下矮高；全部按鈕可操作且無橫向溢出。作業系統開啟減少動效時不應有家具閃爍或拖尾。
11. 在正式部署 GitHub Pages（`import.meta.env.DEV === false`）仍能找到面板，避免只在本機可測；這是**暫時原型**，正式上線前必須移除。
12. 任務進行中不會看到此面板；手動透過 console 送出同名原型指令，也不應修改任務資料。
13. 同一 owned 集合，不論購入順序或重洗路線，其家具排序和座標都相同。八件全滿只出現滿配 JPEG，不重疊八張透明PNG。

## 已知限制／下一批
- 公寓、防空室尚未有專屬家具 PNG 或空屋背景，僅保留圖片占位；預覽倉庫是**開發視覺測試**，不代表公寓已配置倉庫家具。
- 自動建設使用 React 的可取消 timeout，僅在頁面開啟時運行，不會背景繼續建造。
- v0.8.40 才考慮可點擊家具、柔和邊框、指引事件；本批目前只有列表按鈕可操作，不包含熱區及家具真正功能面板。
