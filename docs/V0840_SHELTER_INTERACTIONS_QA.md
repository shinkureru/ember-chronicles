# 第5批 v0.8.40：可點擊家具、Alpha 遮罩與設施提示 QA

## 本批已實作
- `ShelterScene` 使用使用者唯一權威 `warehouse-layout.json` (768×1376) 的原圖位置、尺寸、z、scale、rotation。兩張背景JPG/八張PNG內容完全不變；0件空倉庫、1–7件 PNG 精準疊圖、8件高品質滿場景 JPEG。
- 靜態 PNG 內透明區不會被誤認為可點擊家具。瀏覽器在載入原本的PNG後以約384px縮圖讀取 Alpha≥96，點選時按Z從前到後取第一件有像素的已購入家具。當瀏覽器不允許 canvas 讀取或圖片尚未讀完，仍可藉由小型可聚焦家具標記/鍵盤操作。
- 家具浮標靠PNG實體像素加權重心定位；每件已購入家具一顆，Tab+Enter、滑鼠或手機觸控按鈕可開啟資訊；未買的沒有互動控制。滿8件雖使用乾淨JPG仍顯示8個互動標記和必要的光邊。
- 柔和光邊沿用PNG Alpha mask，只有 hover/目前選擇/尚未讀取的重要通知才出現，約2.8–3.2秒慢速呼吸。作業系統 reduce-motion 時完全取消動畫。
- 8家具資訊面板功能僅預留：床/儲物架/工作台/無線電台/證物調查板/發電機/料理台/電腦桌；查看與關閉無資源、時間或任務副作用。
- 提示測試卡可手動發出教學→調查板、隱藏支線→電腦、製作完成→工作台。必須先購買該件家具，才能模擬對應提示。佇列去重、按先後展示、檢視或忽略可撤銷、移除家具即清掉提醒。**未自動與遊戲任務、NPC、關卡或掉落資料串接**。
- 廢棄公寓/地下防空室仍是原本的圖片占位。設計師可點「預覽倉庫家具建設」測試場景和提示，不會改掉自己選擇的避難所。
- 原型工具尚會在 GitHub Pages 上顯示，正式上架必須撤除/限制。重要提示的真正觸發時機與發電機電量/電腦解密等功能尚待設計師決議。

## 自動測試
- `npm run build` TypeScript + Vite 必須全綠。
- `npm test` 保留既有所有回歸及 PNG/JPG SHA-256 checksum 驗證，加上 `tests/v0840-shelter-interactions.test.ts` 的透明遮罩與Z排序、alpha取樣、手機比例座標換算、佇列提醒、介面及版本驗證。
- GitHub CI 通過不代表已經實際驗收瀏覽器在手機尺寸和真實 pointer 行為上的表現。

## 人工測試流程
1. 已選廢棄倉庫：進入空屋，未買家具時不會有小型互動標記；畫面仍是空倉庫。
2. 開發面板先單獨購買電腦：場景顯示獨立 PNG，電腦上出現小型操作標記。直接點電腦**實體像素**應打開電腦資訊面板，點其透明留白不應打開。
3. 移到標記並用滑鼠、觸控或鍵盤Tab/Enter操作，均應開資訊面板，關閉鈕可以點且不變更存檔。
4. 購入工作台和調查板後模擬「重要隱藏支線」：只有電腦柔和呼吸高亮，提示卡顯示未讀加密訊息。忽略後高亮消失；按檢視設施應打開電腦面板。
5. 依次模擬三類通知，注意按順序輪播、重複點同一提示不產生兩張相同內容；移除電腦後它的提示應被清除，重新購入不應憑空復活舊提示。
6. 一鍵滿配：保持完整高品質 `background_full.jpg`，**不應重疊八張家具實體 PNG**；同時應可點八件家具、動態選擇對應設施面板。
7. 購入 radio 和 workbench 等重疊家具，點真正重疊區看最前面Z大的那一件；透明陰影較薄的區域不應觸發。
8. 重洗家具購買順序，已購入家具熱區、標記及選取不應改動位置。
9. 用 `/#/world-map` 測試舊章節地圖、進任務時不得有避難所互動圖層出現在關卡頁；不影響人物、金錢、飢餓及NPC。
10. 刷新遊戲：家具擁有紀錄仍保存，資訊面板與測試提醒不要求永久保存；遊戲啟動畫面依舊每次播放。
11. 選公寓或防空室時測試倉庫預覽，返回占位畫面，選擇類型仍不變。
12. 測試 Chrome/Edge 桌機 1280、720；手機 320/360/390，橫屏低高度520、200%縮放、Tab焦點以及觸控；留意標記不應遮蔽重要場景細節。
13. 開啟 `prefers-reduced-motion`：沒有連續呼吸光暈或提示閃爍；資訊與操作仍保留。
14. 若 PNG 因儲存限制／CORS 載入失敗，alpha click 可失效，但標記應仍可鍵盤/觸控操作；不能把整張透明圖片矩形當作家具。
15. 親自比對空景/1-7/滿景、床 x=-23、料理台 x=-52、調查板去背及料理台914×1225，確認沒有額外裁切、重去背、錯位及過亮陰影。
