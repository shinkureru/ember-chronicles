# v1.7.2｜旅店入口與戰敗結果畫面修正

狀態：位於 `fix/v1.7.2-inn-and-defeat-persistence` 的待合併修正；以合併 PR #19 和 #20 的 `main` Commit `46ab986b15f4b16024cb0cc72e8a03d38e63d1e2` 為起點。尚待 CI 和實際瀏覽器驗收，勿在合併前宣稱已正式部署。

## 根本原因與修改

### 旅店看似沒有反應
- 既有 `TownPage.tsx` 的「旅店／出租床位」**設施卡片**只做 `setFacility('inn')`。而城鎮頁預設 `facility='inn'`，所以再點這張卡不會產生任何可見變化，與原要求「點旅店卡開視窗」不一致。
- 先前 PR #19 的 `InnRestDialog` Portal 已經存在，但只有捲動到下方的三個服務按鈕才會呼叫 `setRestDialog`。Portal 的修改本身沒有讓設施卡可點開。
- 現在**每次點選旅店設施卡**（包含已選取的卡）會立即開啟 `InnRestDialog`，預設普通床位；視窗內可切換普通床位／安靜單人房／短暫打盹，預覽會隨選擇更新。舊有下方服務按鈕仍可直接進入指定床位的預覽。
- 新視窗以 `onConfirm(selectedBed)` 送出真正選定的服務 ID，避免預覽單人房卻支付普通床位的費用。維持共用的 `previewInnRest`、`getTownServiceLock` 和每日最多兩次限制；滿血/體力仍可開啟並休息。
- 預覽開啟時暫停一般世界時鐘，避免在開啟視窗期間時間跳動造成價格/剩餘次數與結算不同；敵人反擊計時不屬於本視窗場景。

### 戰敗畫面被認為自動關閉
- 現有 `MissionTransition` 程式已在 `kind==='defeat'` 時略過 timer，但 `GameFeedback` 又在收到 `mode='result'` 時顯示短暫的「戰敗」**全域通知**，通知 3.3 秒後會消失。兩個 UI 的共存造成誤以為戰敗結果會自動結束的可能性。
- 統一將「戰敗／任務結果」交給全螢幕 `MissionTransition`。`TRANSITION_DURATION.defeat` 明確設成 `null`，`useEffect` 只替非 `null` 項建立 timer。只有點擊右下角「結束戰敗 · 返回地圖」才觸發 `RETURN_HUB`。
- `GameFeedback` 在進入結果畫面時清除先前排隊的臨時提示，不再生成幾秒鐘就消失的重複「戰敗」通知。
- 勝利／撤退／入場／敵人登場的原有轉場計時不變；不調整戰鬥傷害、NPC、配樂與其他城鎮系統。

## QA 驗收清單

1. 點進城鎮，直接點上方 **旅店／出租床位大卡片**，即使它已經有選取邊框，也必須立即出現休息預覽視窗。
2. 在視窗切換三種床位，生命/體力進度條、建議恢復、費用/分鐘必須隨床位更新；確認使用的是當前床位且實際扣款/恢復一致。
3. 人物 1/10 HP、0/10 體力且有足夠舊幣時，普通床位恢復到 9/10，安靜單人房恢復到 10/10。即使兩項數值全滿也能打開視窗；不足舊幣或今日已休兩次時要顯示清楚的阻擋原因。
4. 在下方展開服務面板點指定床位仍能開啟同一視窗，且初始選項對應被點擊的床位。
5. 角色被敵人反擊擊倒，檢查 **MISSION FAILED** 全螢幕結果停留超過 10 秒仍存在，沒有另一張自動消失的「戰敗」彈窗；僅玩家點擊右下角退出後才回地圖。
6. 確認重新整理瀏覽器時保存結果狀態；按結束鍵時正常整理背包並回城。勝利、撤退的既有過場節奏維持。
7. 檢查 GitHub Actions `npm run build` 和 `npm test` 均通過；PR 合併及 Pages 部署後頁首顯示 **v1.7.2** 和對應的 Commit 短碼。CI 通過不等於實機驗收。
